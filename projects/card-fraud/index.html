Card Transaction Fraud Detection

Only about 1 in 600 card transactions is fraud, and analysts can't review everything. Which transactions should they review first, and how much fraud does a fixed daily review budget actually stop?

2. Model comparison

Four algorithms, tested on the future

Trained on the first 75% of transactions in time order, tested on the last 9.3 hours. PR-AUC is the main metric because fraud is so rare

Random Forest and Gradient Boosting tied in time-series cross-validation, and Random Forest held up best on the unseen hours, so it is the champion. Isolation Forest learns from no fraud labels at all. Its ROC-AUC looks good, but its PR-AUC shows it would bury analysts in false alarms. It is useful as a second-line check for new fraud patterns, not as the main model.

Precision–recall curve

Higher and further right is better. Recall = share of fraud caught, precision = share of alerts that are real fraud

    Method

    Cleaning: removed 1,081 exact duplicate rows and verified no missing values, then sorted by time → 9 SQL queries in SQLite (CASE bands, CTEs, LAG, RANK, running totals and moving averages) → features: 28 PCA components, log amount, hour → time-based 75/25 split (no random shuffling, so the model never sees the future) → 3-fold time-series CV comparing Logistic Regression, Random Forest and Gradient Boosting, plus unsupervised Isolation Forest → alert-budget and cost analysis on the untouched test hours, with an assumed €5 review cost per alert → permutation importance. Dataset: Dal Pozzolo et al. (2015), Worldline & ULB Machine Learning Group.
